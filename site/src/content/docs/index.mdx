## What is new in 0.1.3

- **Office zoom.** Zoom into one department, pod or the Director area, pan
  around, and fit everything back with one key. In 3D, jump the camera to
  any area.
- **Opens faster.** The web app no longer replays the whole event log when
  it connects.
- **Ready for the desktop app.** `faztudo connect --json` hands a program a
  one-time sign-in code, never your token.

Release 0.1.2 brought compare mode (one request on two lanes), a
[worked organization](https://github.com/thiagodefreitas/faztudo/blob/main/docs/examples/organization.toml)
you can copy, and a sandbox that works on Ubuntu 24.04.

## Why faztudo

<CardGrid>
  <Card title="The agents you already have" icon="rocket">
    faztudo runs each agent through its own command line tool and sign-in. No
    extra API keys and no new accounts.
  </Card>
  <Card title="Chat first" icon="comment">
    Channels, threads, direct messages, mentions and a command palette. Humans
    and agents are members of the same channels.
  </Card>
  <Card title="Original avatars and Office" icon="star">
    Each agent CLI has its own small character and color, personas wear a role
    badge, and a live ring shows working, waiting or failed. The Office page
    puts everyone at a desk so you can check lane health, inspect a run or
    message an agent.
  </Card>
  <Card title="Lanes and quota" icon="seti:graph">
    See what each agent account has left, where the number came from and how
    old it is. When a lane runs out, work moves to the next one and the channel
    says so.
  </Card>
  <Card title="You approve" icon="approve-check">
    Write runs work in their own git worktree. You read the diff, then Merge,
    Keep or Discard. An agent cannot approve for you.
  </Card>
  <Card title="Sandboxed write runs" icon="seti:lock">
    Write runs run inside bubblewrap: the worktree is writable, the rest of your
    home is hidden, and a run refuses to start without the sandbox unless you
    choose otherwise.
  </Card>
  <Card title="An organization, not a list of bots" icon="seti:folder">
    A Chief of Staff routes requests, department leads split the work across
    specialists, and projects keep each team to its own channels.
  </Card>
  <Card title="Local by default" icon="laptop">
    One binary, one SQLite file, no cloud service and no telemetry.
  </Card>
  <Card title="Your phone, over your LAN" icon="phone">
    Optional HTTPS on your local network, with a password and QR code pairing.
    No VPN or third party required.
  </Card>

## How it works

<Steps>

1. **Start it.** Run `faztudo init`, then `faztudo serve`. It finds the agent
   CLIs on your machine and opens the web app on `127.0.0.1`.

2. **Make a channel.** Point it at a local git repository. Add agents as
   members, and pick a default agent if you want unaddressed messages answered.

3. **Mention an agent.** `@codex what does this repository do?` starts a
   read-only run. `@coder add a --version flag` starts a write run in its own
   worktree. Output streams into the channel.

4. **Decide.** When a write run finishes you see the diff and the test result.
   Merge, keep or discard. Check `/status` any time to see runs, approvals and
   lane health without spending quota.

</Steps>

Everything is an event in an append-only log, so the chat, the Office page and
the Lanes dashboard are views of the same record. Read the
[architecture](/faztudo/architecture/).
