## What is new in 0.1.7

- **See what an agent was given.** A run's Context tab shows the exact
  prompt, section by section with sizes: the channel summary, the other
  work in progress, the pins, the transcript, the request and the
  instructions.
- **All work in one place.** The Tasks page has an All work view of every
  run of the last day, including mentions and delegations, with who handed
  each one out.
- **An office that fits the screen.** The 2D office lays out its rooms to
  fill the window, and each working desk shows what it works on.
- **Summaries and lanes that work.** Channel summaries never ran before:
  their prompt was too long for one command-line argument. Lanes that ran
  out of quota come back at their reset time, and a lane that just ran
  cleanly shows as available.
- **Private channels stay private.** Runs of a private channel, with their
  output, diffs and prompts, are hidden from members outside it.

## Earlier: 0.1.5 and 0.1.6

- **0.1.6 fixes channel switching.** In 0.1.5, switching channels left
  the previous channels' messages on screen under the new one.

- **Agents share the work.** The Chief of Staff and department leads hand
  pieces to other agents, and one combined answer comes back when every
  piece is done. Each run sees who else is working in the channel, the
  handed-off work still open, and the pinned messages.
- **Agents read more of the project.** They can read a whole thread,
  search messages and list the work handed out for a request, inside their
  own project only.
- **A smoother chat.** Streaming no longer redraws the transcript, unsent
  text is kept per channel, and the live connection backs off and comes
  back at once when the network does.
- **Clearer failures.** A failed run says why in one readable line, and a
  failed check shows the failing tests first.
- **Steadier runs.** Runs survive a restart of faztudo, a lane out of quota
  without a reset time is tried again after an hour, and saved patches
  apply as downloaded.

Release 0.1.4 brought the Linux desktop app, `faztudo stop` and Signal
linking.

## How it works

<Steps>

1. **Start it.** Run `faztudo init`, then `faztudo serve`. It finds the agent
   CLIs on your machine and opens the web app on `127.0.0.1`.

2. **Make a channel.** Point it at a local git repository. Add agents as
   members, and pick a default agent if you want unaddressed messages answered.

3. **Mention an agent.** `@codex what does this repository do?` starts a
   read-only run. `@coder add a --version flag` starts a write run in its own
   worktree. Output streams into the channel.

4. **Decide.** When a write run finishes you see the diff and the test result.
   Merge, keep or discard. Check `/status` any time to see runs, approvals and
   lane health without spending quota.

</Steps>

Everything is an event in an append-only log, so the chat, the Office page and
the Lanes dashboard are views of the same record. Read the
[architecture](/faztudo/architecture/).

## Built with faztudo

faztudo is developed with faztudo. The maintainer posts a short brief in a
project channel, write runs do the work in their own git worktrees, a reviewer
on another model reads the diff, and a human approves and commits -- agents
never commit. The dogfood instance logged 118 agent runs across 10 lanes since
2026-10-17. Read the
[Built with faztudo](https://github.com/thiagodefreitas/faztudo/wiki/Built-with-faztudo)
wiki page for the numbers, the workflow and what dogfooding found.
